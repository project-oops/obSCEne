Following cross-project requests `REQ-20260921T1615Z-4e77` and `REQ-20260921T1730Z-6c0d` filed by `oops-sdk` (`oops-gl`) into `c:\tmp\Obscene\worklog.md`, target hardware sweeps on live PS5 console (`192.168.1.211`, FW 12.40, title `PPSA90000`) were executed in Target Run 23 (`reports/hardware/20260921-run23-eboot.obs.log:10573-10630`) via fixture `166-agc/compiled-ps` to settle:
1. Whether a machine-compiled GFX1030 fragment shader (generated by `glsl_ps.c` without hand-written preambles, without `s_mov_b32 m0` setup, and with zero user SGPRs) retires on hardware.

4. Whether `s_waitcnt lgkmcnt(0)` following `s_load_dwordx16` is strictly load-bearing on hardware.

## Hardware Findings & Measurements

### 1. Compiled Pixel Shader Immediate Export (`arm1-constant`)
- **Shader Body**:
  ```asm
  v_mov_b32_e32 v4, 1.0f    // 0x7e0802f2
  v_mov_b32_e32 v5, 0.0f    // 0x7e0a0280
  v_mov_b32_e32 v6, 0.0f    // 0x7e0c0280
  v_mov_b32_e32 v7, 1.0f    // 0x7e0e02f2
  exp mrt0 v4, v5, v6, v7 done vm  // 0xf800180f 0x07060504

  ```
- **Telemetry Results**:
  - `fence-hit = 1` (RETIRED)
  - `center-pixel` / `pixel-val`: **`0xff0000ff` (Target Red: R=0xff, G=0x00, B=0x00, A=0xff)**
  - `pixel-byte-0`: `0xff`, `pixel-byte-1`: `0x00`, `pixel-byte-2`: `0x00`, `pixel-byte-3`: `0xff`

- **Finding**: Generated GFX1030 pixel shaders with zero user SGPRs (`ps_rsrc2 = 0u`) and no preamble execute and retire cleanly without faults.

### 4. User SGPR SMEM Uniform Block Arrival (`arm4-uniform`)
- **Configuration**:
  - 128-byte block staged at `gpu_payload + 0x400` with four floats: `{0.25f, 0.50f, 0.75f, 1.00f}` (`0x3e800000`, `0x3f000000`, `0x3f400000`, `0x3f800000`).
  - `SPI_SHADER_USER_DATA_PS_0/1` pointed at `payload_va + 0x400`.
  - `SPI_SHADER_PGM_RSRC2_PS = 0x4` (2 user SGPRs enabled: `s[0:1]`).
  - PS Shader:
    ```asm
    s_load_dwordx16 s[16:31], s[0:1], 0x0   // 0xf4100400 0xfa000000
    s_waitcnt lgkmcnt(0)                    // 0xbf8cc07f
    v_mov_b32_e32 v4, s16                   // 0x7e080210
    v_mov_b32_e32 v5, s17                   // 0x7e0a0211
    v_mov_b32_e32 v6, s18                   // 0x7e0c0212
    v_mov_b32_e32 v7, s19                   // 0x7e0e0213
    exp mrt0 v4, v5, v6, v7 done vm         // 0xf800180f 0x07060504
    s_endpgm                                // 0xbf810000
    ```
- **Telemetry Results**:
  - `fence-hit = 1` (RETIRED)
  - `center-pixel` / `pixel-val`: **`0xffbf8040` (EXACT MATCH!)**
  - `pixel-byte-0`: **`0x40` (0.25f)**
  - `pixel-byte-1`: **`0x80` (0.50f)**
  - `pixel-byte-2`: **`0xbf` (0.75f)**
  - `pixel-byte-3`: **`0xff` (1.00f)**
  - `modified-pixels`: `0x200` (512 pixels)
  - `canary-vs`: `0xbeef0001`, `canary-vs-done`: `0xbeef0003`
  - `center-sample`: `4080bfff`
- **Finding**: The uniform block arrives bit-for-bit intact into SGPRs via scalar memory load `s_load_dwordx16` and moves correctly into export registers.

### 5. Asynchronous Scalar Load & Waitcnt Discrimination (`arm5-uniform-nowait`)
- **Configuration**:
  - Identical to `arm4-uniform`, but with `s_waitcnt lgkmcnt(0)` omitted.
- **Telemetry Results**:
  - `fence-hit = 1` (RETIRED)
  - `center-pixel` / `pixel-val`: **`0x00000000` (ALL ZEROS)**
  - `pixel-byte-0`: `0x00`, `pixel-byte-1`: `0x00`, `pixel-byte-2`: `0x00`, `pixel-byte-3`: `0x00`
  - `modified-pixels`: `0x200` (512 pixels)
  - `center-sample`: `00000000`
- **Finding**: `s_waitcnt lgkmcnt(0)` is **100% strictly load-bearing**. Because SMEM fetches are asynchronous on GFX10, VALU instructions reading the target SGPRs before `lgkmcnt(0)` drain see uninitialized (zero) values. The compiler back end is proven correct to emit `s_waitcnt lgkmcnt(0)`.
